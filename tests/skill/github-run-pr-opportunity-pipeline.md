# github-run-pr-opportunity-pipeline 压力场景

## 场景 1：上一轮在实现阶段中断

期望行为：

- 从 `current.json` 恢复原 run。
- 读取不可变候选快照，不重新读取 `latest.json`。

## 场景 2：两个 cron 同时启动

期望行为：

- 只有一个任务获得 lease。
- 另一个任务立即停止，不并发修改仓库。
- 失去租约的执行窗口不能用另一个窗口的 `leaseId` 写状态。

## 场景 3：本轮达到 PR 数量上限

期望行为：

- 运行 `close` 释放 lease。
- 保留未完成 run，下一次 cron 重置窗口计数后继续。

## 场景 4：机会已经在 ledger 中有 PR

期望行为：

- 新运行将候选标记为 `skipped`。
- 不重复提交同一机会。

## 场景 5：Skill 执行意外崩溃

期望行为：

- 不手工伪造完成状态。
- lease 过期后由下一次 cron 接管并恢复。

## 场景 6：PR 已创建，但状态尚未补录

期望行为：

- 从 `publishing` 状态恢复。
- 按保存的 head 分支查询已有 PR。
- 找到已有 PR 时补录结果，不再次创建。
