# GitHub 热门项目 PR 展示页范围决策

## 已确认决策

用户选择方案 B，但首版只需要一个展示页面：

- 用表格展示每日看到的热门项目。
- 展示每个项目可提交 PR 的切入口。
- 展示潜在 PR 风险。
- 展示建议从什么角度切入贡献。
- 不添加任何按钮。
- 不在页面内做确认、提交、fork、建分支等操作。
- 用户阅读页面后，在对话中指定需要继续做哪一个项目。

## 设计影响

- 页面是只读报告，不是操作后台。
- 数据结构要优先服务扫描、比较和决策。
- 每行需要足够的信息帮助用户判断是否值得继续推进。
- 后续“继续做某个项目”的执行流程应由单独命令或对话触发。
