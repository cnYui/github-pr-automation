# czlonkowski/n8n-mcp PR 计划

## 目标

给 `czlonkowski/n8n-mcp` 提交一个低风险 PR，聚焦 issue `#814` 中 HTTP MCP 客户端嵌套数组/对象序列化不稳定的问题。

## 当前证据

- 当前项目日报把 `czlonkowski/n8n-mcp` 标记为 `值得继续`，推荐切口是“HTTP MCP 客户端序列化”和“partial workflow 更新回归测试”。
- 上游默认分支是 `main`，当前 HEAD 为 `9e30942e71c4a746da0769239ba82214776d79e1`。
- 上游开放 issue `#814` 描述：部分 HTTP MCP 客户端会把 `position: [x, y]` 传成 `{ "0": x, "1": y }`，把 `typeVersion: 1` 传成 `"1"`，把 `parameters: {}` 传成 `"{}"`。
- 上游已有开放 PR 处理 `nodeGroups` / `sourceWorkflowId` 等 PUT additional properties 问题；本次不碰该方向，避免重复。

## 设计

本次 PR 只做 MCP 输入归一化，不改变业务校验规则。

核心思路：

1. 保留 `workflowNodeSchema` 对真实 n8n workflow 节点的语义要求：`typeVersion` 必须是数字，`position` 必须是二元数组，`parameters` 必须是对象。
2. 在 schema 前增加窄范围预处理，把 HTTP MCP 客户端常见的传输变形恢复成正常 JSON 形状。
3. 覆盖 `n8n_create_workflow` / `n8n_update_full_workflow` 共享的节点校验路径，以及 `n8n_update_partial_workflow` 的 `addNode.node` 子对象。

不做：

- 不修 `nodeGroups`、`sourceWorkflowId` 或其它 PUT body additional properties。
- 不接入真实 n8n 实例做集成验证。
- 不扩大到所有未知对象的强制转换，避免把本该失败的输入吞掉。

## 实现计划

1. 在上游仓库创建分支 `codex/normalize-http-mcp-workflow-input`。
2. 先在 `tests/unit/services/n8n-validation.test.ts` 添加失败测试：
   - `workflowNodeSchema` 能接收 `position` 的数字索引对象。
   - `workflowNodeSchema` 能接收字符串数字 `typeVersion`。
   - `workflowNodeSchema` 能接收 JSON 字符串形式的 `parameters`。
3. 如 partial update 的 schema 可直接单测，再给 `tests/unit/mcp/handlers-workflow-diff.test.ts` 或现有对应测试补 `addNode.node` 的输入归一化测试；若 handler 需要 API mock 成本过高，则先把归一化函数放在可单测的 services 层。
4. 运行相关测试，确认新增测试先失败。
5. 最小实现：
   - 新增或复用一个 `normalizeMcpJsonInput` 类工具函数。
   - 在 `workflowNodeSchema` 的 `typeVersion`、`position`、`parameters` 字段上使用预处理。
   - 在 partial update `node` 字段上复用同一归一化路径。
6. 运行相关单测，确认变绿。
7. 跑 `npm run typecheck` 和 `npm run build`。
8. 自查 diff，只提交上游仓库相关文件。
9. 推送到 `cnYui/n8n-mcp` 分支并向 `czlonkowski/n8n-mcp:main` 创建 PR。
