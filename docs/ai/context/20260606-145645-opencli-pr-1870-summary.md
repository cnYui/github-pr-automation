## 改动

- 修改 `src/browser/base-page.ts`
  - `installInterceptor(pattern)` 继续通过 `evaluate()` 注入当前 document。
  - 当 page 暴露 CDP 时，额外调用 `Page.addScriptToEvaluateOnNewDocument`，让后续导航的新 document 自动安装同一个 fetch/XHR interceptor。
  - CDP 注册失败时不阻断当前 document 注入，保持非 CDP 后端兼容。
- 修改 `src/browser/base-page.test.ts`
  - 新增测试：CDP 可用时会注册 future-document interceptor。
  - 新增测试：CDP 注册失败时当前 document interceptor 仍保留。

## 环境说明

- `npm install` 在 Windows 上因上游 `prepare` 脚本使用 POSIX 写法失败：`[ -d src ] && npm run build || true`。
- 本地改用 `npm install --ignore-scripts` 安装依赖。
- `npm install` 产生的 `package-lock.json` 元数据改动已清理，PR 只包含实现和测试。
- GitHub Advanced Security secret scanning 对该仓库不可用；本次 diff 人工检查只包含测试字符串和拦截器逻辑。

## 剩余风险

- 修复覆盖的是「安装 interceptor 后发生的导航」。如果用户先 `goto(..., { waitUntil: 'none' })`，再安装 interceptor，仍可能错过页面最早发出的请求。
- 未跑完整 `npm test`，本轮以相关单测和类型检查作为最小验证闸门。
