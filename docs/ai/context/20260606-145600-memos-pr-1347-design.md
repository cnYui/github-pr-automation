## 方案比较

### 方案 A：把自动召回最小长度默认改成 10

优点：默认即可减少短词污染。
缺点：会改变现有用户行为，英文短但有语义的查询如 `Docker?` 可能被跳过。

### 方案 B：新增 `recall.autoRecallMinQueryLength`，默认保持旧行为

优点：只给自动召回新增可配置阈值，不影响手动 `memory_search`；默认兼容现有行为；用户可按 issue 建议设为 10。
缺点：需要用户显式配置才会改变运行时行为。

### 方案 C：增加 LLM/topic judge 过滤短查询

优点：语义判断更细。
缺点：成本高，和已有 topic pre-filter 方向的开放 PR 重叠，范围不适合作为小 PR。

## 选择

采用方案 B。

实现只改自动召回入口：

- 在 `MemosLocalConfig.recall` 中新增 `autoRecallMinQueryLength?: number`。
- 在 `DEFAULTS` 和 `resolveConfig()` 中设置默认值为 2，等价于当前 `query.length < 2` 的行为。
- 在 `before_prompt_build` 自动召回 hook 中读取 `ctx.config.recall.autoRecallMinQueryLength`，短于阈值时直接跳过本地和 Hub 搜索。
- 同步 `packages/memos-core` 中的镜像类型和配置，避免两个源码树漂移。
- 在 README 的 recall 配置示例中说明可设为 10 来过滤短确认词。
