# n8n #32854 最小 PR 设计

## 背景

目标仓库：`n8n-io/n8n`

目标 issue：`#32854 Docs: MCP "document_processing" best-practices states Extract from File output key is "text"; default is "data"`

已确认事实：

- issue 明确指出问题在 MCP `get_workflow_best_practices(technique: "document_processing")`
- 相关文案位于 `packages/@n8n/workflow-sdk/src/prompts/best-practices/guides/document-processing.ts`
- MCP 工具测试位于 `packages/cli/src/modules/mcp/__tests__/get-workflow-best-practices.tool.test.ts`
- 当前未发现直接覆盖 `#32854` 的 open PR

## 问题

当前 `document_processing` 指南里，`Extract from File` 的默认输出 key 示例写成了 `{{ $json.text }}`。这与 issue 描述和节点默认行为不一致：默认 `destinationKey` 是 `data`，用户按当前文案照做会拿到空值或 `undefined`。

这不是 runtime bug，而是 MCP best-practices 文案 bug。

## 目标

提交一个最小 PR，修正 `document_processing` 指南中的错误默认输出 key 文案，并用测试把这个文案锁住，避免后续回归。

## 非目标

- 不修改 `Extract from File` 节点 runtime 行为
- 不扩写整个 `document_processing` 指南
- 不顺手修其他文档、节点说明或 prompt 内容
- 不把 `destinationKey` 的所有变体全部展开成大篇幅说明

## 备选方案

1. 只改文案，不补测试
   - 优点：改动最小
   - 缺点：`n8n` 的 PR 期望 bugfix 有测试，且后续更容易被误改回来

2. 改文案，并在 MCP 工具测试里补定向断言
   - 优点：范围仍然很小，但能把错误示例固定住
   - 缺点：要读一层 MCP best-practices 输出测试结构

3. 全面审计并重写 `document_processing` 的 Extract / key 输出说明
   - 优点：覆盖更广
   - 缺点：超出 `#32854`，风险和 review 成本都会上升

## 选择

采用方案 2。

原因：

- 它满足最小 PR 的要求
- 它直接闭合 issue 指向的问题
- 它符合 `n8n` 对 bugfix 补测试的预期
- 它不会把一个局部文案错误扩成一次大范围内容重写

## 设计

只改两个文件：

1. `packages/@n8n/workflow-sdk/src/prompts/best-practices/guides/document-processing.ts`
   - 把默认访问示例从 `{{ $json.text }}` 改成 `{{ $json.data }}`
   - 补一句默认 key 是 `data`，并可通过 `destinationKey` 配置覆盖

2. `packages/cli/src/modules/mcp/__tests__/get-workflow-best-practices.tool.test.ts`
   - 增加针对 `document_processing` 输出的定向断言
   - 断言结果包含 `$json.data`
   - 断言结果不再包含错误的 `$json.text` 默认示例

## 风险

- 如果测试当前使用快照或大段文本比对，新增断言时要避免让测试变脆
- 如果仓内还有其他 prompt 或 docs 副本引用同一句文案，需要确认本次只修 MCP best-practices 主来源是否足够

## 验证

- 跑目标测试文件，确认 best-practices MCP 输出已包含正确示例
- `git diff --check`
- 必要时全文搜索，确认旧错误默认示例已从目标指南移除

## 预期产出

- 一个只修 `#32854` 的最小 PR
- 改动集中在 best-practices 文案和对应测试
- PR 描述明确说明这是文档 / guidance 修复，不是 runtime 逻辑变更
