# GitHub 热门项目 PR 助手首版运行方式决策

## 已确认决策

首版采用：

- 本地每日任务。
- 命令行审核队列。
- 自动抓取、筛选、分析并生成候选 PR 报告。
- 用户在 CLI 中逐个确认后，系统才执行 fork、建分支、提交和打开 PR。

## 选择原因

- 首版更快落地，不需要先建设 Web 后台。
- 用户可以直接检查 patch、测试结果和 PR 草稿。
- 人工确认能避免低质量或不符合维护者预期的 PR。

## 设计影响

- 系统需要持久化每日候选队列、分析结果、生成 patch、验证日志和确认状态。
- 提交动作必须是显式交互命令，不能由定时任务自动触发。
- 后续可以在 CLI 稳定后再扩展 Web 审核界面。
