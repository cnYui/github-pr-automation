# GitHub 热门项目 PR 自动化初始上下文

## 用户目标

用户希望每天自动从 GitHub 找到“新标”排行前十的热门项目，并为 10 个项目寻找可提交 PR 的切入口；每天至少向 5 个项目提交 PR，且项目必须足够热门。

## 必须先澄清的边界

- “新标”需要定义：可能是最近 24 小时新增 star、GitHub Trending、短期 star velocity、或其他指标。
- “提交 PR”不能只按数量驱动，否则容易产生低质量 PR，影响开源维护者。
- 合理设计应优先做成“发现机会、验证价值、生成候选补丁、人工确认后提交”的贡献助手，而不是无人值守批量提交 PR。
- 每日目标可以设计为“至少 5 个高质量候选 PR 进入人工确认队列”，最终提交数量由质量门槛决定。

## 初步安全原则

- 不自动向无关热门仓库提交机械化 PR。
- 不以刷量、蹭热度为成功指标。
- 必须尊重项目贡献指南、issue/PR 模板、许可证、维护者偏好和 CI 要求。
- 只有满足明确价值、通过本地验证、符合仓库规范的候选变更才允许进入提交阶段。
